## Duplicate-suppression gate (adversarial reviewer — runs after the table is built, BEFORE the chart is saved)

The author of the chart does not clear its own duplicates. After the table is produced but before saving, spawn a read-only adversarial reviewer (Agent tool, `subagent_type: Explore`) that did NOT build the chart. Hand it the proposed rows + the repo, and have it independently:
1. Check the commits (`git log -20 --stat` for topic context + `git log -p -- <target>` per row, and `reports/mindmap-pass/*.md`), without trusting the author's dedup. Also run `python3 scripts/mindmap/coverage_lookup.py --site-url <BASE_URL> --chart <draft chart>` yourself and check every row's `lookup:` claim against the tool's output — a row that names no match while the tool lists a page with the same reader intent, or that omits a `lookup:` entry, fails the gate. The tool runs the same everywhere (cloud included), so when no reviewer subagent can be spawned the orchestrator runs it inline and records that it did.
2. For each row, decide whether the work is **already shipped** per the three-bucket duplicate definitions (page created / body section added / metadata rewritten for that term).
3. Return `KEEP` or `DROP — already shipped in <SHA>`, SHA cited.
4. **Cluster rows get TWO extra checks (Lens 2 integrity):**
   - **Real evidence:** the cluster's member phrases must actually come from SEMRUSH/Autocomplete/the brief — not invented. A cluster built on unsupported phrases → `DROP — unsupported`.
   - **Right lever:** verify no existing page is already the dedicated, intent-matched answer. If one is, `create new content` is wrong → `RECLASSIFY — <correct bucket>` (or `DROP` if fully served). Conversely, if a row enriches a page that isn't a reasonable home, `RECLASSIFY — create new content`.
   - Every cluster row in the main table must have a matching row in the `## Emerging search patterns (clusters)` block (same bucket + target). A mismatch fails the gate.

**Gate rule:** if the reviewer flags ANY row as already-shipped or unsupported, remove it from the table (and clusters block) and record it under exclusions. Apply any `RECLASSIFY` in BOTH the table and the block. Before dispatch, apply the independent chart review limit in `_mindmap-execution.md` to the original job and its existing rounds. The chart saves only once the reviewer confirms **zero** surviving rows duplicate shipped work, every cluster row is evidence-supported and correctly leveled, and table + block agree. A row without a cited SHA (or "no prior commits touch this file/route") is unverified and fails the gate. At the permitted limit retain unresolved findings and accept only an exact chart the reviewer actually approved.
