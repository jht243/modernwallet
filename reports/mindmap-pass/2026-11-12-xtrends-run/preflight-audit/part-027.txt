### Rung 2 — REWORK (back to the writer, this page only)

Reserved for findings that need new substance, new research, or a structurally different page:

- a claim `content_gen.py fix` reported NOT FIXABLE IN PLACE (the page needs a fact it does not have)
- depth under the floor after unsupported claims were removed, or a page that can only reach its floor by restating the same facts: EXPAND THE CLOSED FACT LIST with sourced facts first (the draft meta's `thin fact list` flag says so), then regenerate; never pad, never loosen the audit
- an experience claim `_experience.md` does not license
- the wrong register for what the page does
- depth under the floor for its page type
- a missing required page element (direct answer up top, who-this-is-not-for, what-would-change-our-answer, the proprietary anchor)
- a dead-end problem the page raises and never resolves
- a section that has to be rewritten rather than repaired

Hand the reviewer's notes for **that page only** to the writer phase and re-run it for that page. A regenerated API page gets the claim check again automatically; anything the audit still finds goes back through Rung 1 `fix`, not straight to another rework. The reworked page then gets a full audit again, from Rung 0.

**One shared Mindmap audit budget.** An activated Mindmap page has its configured total 1/2/3 independent rounds, including corrections; there is no separate two-rework allowance. At its limit stop editorial work and publish the exact final reviewed candidate with factual/cosmetic FAIL findings intact. Preserve unrelated work and unchanged-page evidence. Non-Mindmap native workflows retain their own existing limits and explicit client/upsell release exceptions.

---

## PER-PAGE PASS STATE

A page that PASSED stays passed. Fixing or reworking one page does not re-open the audit on its siblings, and the rework counter is **per page**, never per phase. This is what stops one bad page from consuming both attempts on behalf of a batch that was otherwise fine.

This does not weaken the re-audit invariant: a page whose own text changed is always re-checked on that exact text (Rung 1 re-reads the edited fields in context; Rung 2 re-audits the page in full). What is forbidden is re-auditing a page whose bytes did not change.

The reviewer report ends with one line per page:

```
<page>: PASS | FIX-IN-PLACE (n) | REWORK (attempt k/2) | BLOCKED — <reason>
```

## Actual dependency failures

A required lint/build/runtime, canonical instruction, independent-review execution, scope/payment/ownership, testing-honesty, exclusion, explicit customer-hold or professional-approval dependency remains required. Repair it automatically within existing authority, retaining exact work and evidence; report an actual unavailable dependency honestly. An ordinary editorial FAIL at an activated Mindmap audit limit is a capped release, not such a hold. Never fabricate a PASS or silently add another audit. Other native workflows retain their own stop/release rules.
