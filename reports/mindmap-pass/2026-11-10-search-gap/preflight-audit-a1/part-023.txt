## THE LADDER

A finding is fixed at the **cheapest rung that can fix it**. Never send a one-line fix through a full writer re-run and a full re-audit of every page.

### Rung 0 — mechanical lint, before any reviewer reads a word

Run the repo's mechanical content lint on every page the writer phase produced or materially edited:

```bash
npx tsx scripts/content_lint.mts --slug <slug> [--slug <slug> …]     # TS/JS repos
python3 scripts/content_lint.py --slug <slug> [--slug <slug> …]      # markdown/frontmatter repos
```

The lint covers **only black-and-white rules**: em-dash, exclamation mark, heading not in Title Case, meta title and description length, missing required fields, an unsubstituted `{BUSINESS_NAME}`, a malformed or duplicate slug, and a dead internal link. Any FAIL → apply the fix directly (the message names the file, the field, and the offending text) and re-run until it exits 0.

Lint findings **never reach the reviewer, never count as a rework attempt, and never trigger a standard reload.** If the writer phase skipped the lint, run it here first — do not start the reviewer checklist on a page that still fails it.
