## Root cause — this is almost entirely a repeat of the 2026-07-14 finding, not a new defect

build (verified by building the site with `npm run build` and parsing every emitted
`dist/**/index.html` for `href` targets — 0 orphans found). Two things are going on:

1. **146 of 179 URLs are the exact same URLs the 2026-07-14 indexing-pass already diagnosed and
   fixed** (`5783b81`, plus `edbdb6d` for one page, plus the 2026-07-18 `/roundup/` fix `0e855bd`
   for the last one). Google simply hasn't recrawled/indexed them yet — normal for ~150 long-tail
   pages 1–2 weeks post-fix. **No code change is needed or made this run** — see Step D.1 ledger
   below.
2. **33 of 179 URLs are pages published in the last 1–6 days** (the compliance vertical `1cfdd45`,
   10 competitor-monitor guides, 2 new portfolio calculators, 7 new `/compare/` pages, 1 new
   roundup) that were built with a genuine inbound link from day one. They were simply never
   discovered/crawled yet — again, no linking defect, no code change needed.

The only action this run takes for the 33 not-previously-diagnosed URLs is **re-submission**
(IndexNow + Google Indexing API, Phase 7) to prompt a first crawl. The 146 already-diagnosed URLs
get **no re-submission** (Step D.1 rule — a repeat submission for an unchanged page that was
already fixed and already awaiting recrawl adds no signal).
