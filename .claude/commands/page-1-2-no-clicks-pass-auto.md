## Why this routine exists (2026-10-07 analysis, `reports/zero-click-analysis/2026-10-07.md`)

Of 2,332 mature layer3 pages, 958 had ≤3 clicks in 90 days — almost all indexed and shown. Pages on
page 1–2 with thousands of impressions and no clicks fail for different reasons, so one rewrite
doesn't fit all:
- **SNIPPET (#1–10):** searchers see us and pick another result. Nutshell: every other result said
  "$13/user/month", our page said "$7" — a stale fact. Fix what they see: the facts, the title and
  description, and an opening that answers the search.
- **RANK (#11–20):** page 2 gets almost no clicks whatever the title says. Fix why Google ranks it at
  #12: answer faster than the page-1 results, answer Google's People-also-ask questions, add internal links
  (both examples had ONE link pointing at them).
- **Never fixable:** AI-agent/operator queries and navigational searches — detect.py drops them.

## ‼️ THE DATA RULE — Google first-party only, hard fail otherwise

Every number about **our site** (which pages qualify, impressions, clicks, CTR, positions, the 28-day
verdict) comes from Search Console, GA4 and the Google Search Status Dashboard via `scripts/page12/detect.py`
and `scripts/page12/measure.py`. FORBIDDEN for any measurement of our site: Ahrefs, SEMrush,
DataForSEO, any estimate or cached report. No fallback rung.

**The one third-party exception:** DataForSEO may be called ONLY through `scripts/page12/serp_read.py`,
ONLY in Phase 1, to read what the OTHER results show for each page's main search (titles, snippets,
People also ask, AI Overview). Its file is stamped `third_party: dataforseo, purpose: serp_snippets_only`;
nothing in it is ever a number about our site.

**Hard fail:** `detect.py` non-zero (10 credentials · 11 auth · 12 API · 13 stale · 14 empty · 15
truncated), `verify_provenance.py` non-zero (exit 20) at the start of any later phase, or `measure.py`
non-zero → edit nothing, commit nothing except the FAIL report, send the email with `--status failure`,
headline `Page 1-2 No Clicks: HARD FAIL — Google data unavailable`, exit.

## ‼️ THE TWO AUDIT SCOPES (owner rule, 2026-10-07)

| what | scope |
|---|---|
| Writing quality — anti-AI tells, style, voice, lint, link rules | **only the text this run added or changed.** Text already on the page is what Google shows today; it is never graded or "improved". `lint_new_text.py` enforces this in code. |
| **Facts — anything wrong or outdated** | **the whole page.** Every outdated or wrong fact anywhere on the page is corrected with a sentence-level old→new pair and an official source. |

Nothing already on the page is rewritten or removed except: the title and description, and sentences
that state an outdated/wrong fact. The answer block is ADDED above the existing intro.

## Site config & rules

`scripts/rank_drop/site.json` (base URL, GSC + GA4 property, backend, price ledger, IndexNow key) — the
same file rank-drop uses; never type site values into commands.

| rule | value |
|---|---|
| Pages fixed per run | **8** (`PAGE12_PICK`), highest expected click gain first |
| Eligible | 500+ impressions/90d, main real search at #1–20, page CTR < 40% of this site's median CTR for that position band, page 45+ days old, ≤50% synthetic impressions |
| Per-page cooldown | **35 days** (ledger) |
| Shared lock | skip any page ANY routine edited in the last 14 days (detect.py checks git) |
| AI-cited pages | marked (`ai_cited`), fixed additively, never removed |
| **Top pages** | GA4 top 30 (90d sessions) or 100+ Google clicks/month → **FACTS lane**: outdated facts corrected, NO title/description/section/link change. Up to 3 per run, on top of the 8 |
| Visible "updated" date | bumped ONLY by a real content change (new section, fact fix) — never by a title/description or wording edit (Google: no fake freshness) |
| Ledger | `reports/page-1-2-no-clicks/ledger.jsonl` |
| Reports | `reports/page-1-2-no-clicks/<D>.{json,md}` + `.measure.{json,md}` + `<D>/packets/` |

Postgres sites (`"backend": "pg_rows"`): follow the `pg_mcp.py` steps exactly as `rank-drop-recovery-auto.md` § Site config describes, with this routine's packets dir.

## Phase 0 — Detect + measure (Google only)

**Run every Phase 0 command in the FOREGROUND with the Bash `timeout` set to 600000 (10 min).**
`detect.py` pulls 90 days of page×query data and takes ~6 minutes; at the default 120 s timeout the
call is moved to the background and the run stalls waiting on it (first live run, 2026-10-07). Never
background it, never end your turn while it runs.

```bash
python3 -m pip install -q google-auth requests      # python3 -m pip: the sandbox's bare `pip` is a different Python
python3 -c 'import google.oauth2.service_account, google.auth.transport.requests' 2>/dev/null || \
  python3 -m pip install -q --ignore-installed cryptography cffi    # broken system cryptography → exit 10 otherwise
python3 -c 'import json;[print(c) for c in json.load(open("scripts/rank_drop/site.json")).get("setup",[])]' | sh
D=$(date -u +%F)
OUT=reports/page-1-2-no-clicks/$D; [ -f $OUT.json ] && OUT=$OUT-$(date -u +%H%M)   # 2nd run today: never overwrite run 1's report
python3 scripts/page12/detect.py --out $OUT || HARD_FAIL
python3 scripts/rank_drop/verify_provenance.py $OUT.json || HARD_FAIL
python3 scripts/page12/measure.py --out reports/page-1-2-no-clicks/$D.measure || HARD_FAIL
```
Read `$OUT.md` and `$D.measure.md`. Use `$OUT` (not `$D`) for every detect-report path below. A Google ranking update in progress does NOT stop this routine
(titles, facts and an answer block don't chase moving rankings); detect.py records it and measure.py
flags those windows.

**Measurement follow-through (before any new fix):** for every `WORSE` row in `$D.measure.json`, run
`RD_ENGINE=page-1-2-no-clicks-pass python3 scripts/rank_drop/revert_page.py --path <path> --sha <first_sha> --date $D`
and mark that ledger row `status: reverted` (edit only that row's status field in
`reports/page-1-2-no-clicks/ledger.jsonl`). Reverts deploy with the run.

**No pages picked** (`pages` empty) → commit the reports, send the email (Email section), exit. Success, not failure.

## Phase 1 — Packets, SERP read, diagnosis (code, ~2 min)

```bash
P=$OUT/packets
python3 scripts/page12/prepare.py --detect $OUT.json --out $P
DATAFORSEO_B64=… python3 scripts/page12/serp_read.py --packets $P
python3 scripts/page12/diagnose.py --packets $P          # <slug>/diagnosis.json + $P/diagnosis.md
RD_ENGINE=page-1-2-no-clicks-pass python3 scripts/rank_drop/apply_data_refresh.py --packets $P --date $D
```
`diagnose.py` gives each page: **L3 METADATA** (SNIPPET lane), **L4 SECTION** (answer block — RANK lane
always, SNIPPET lane when the opening doesn't answer the main search), `fact_check` (figures 2+ other
results agree on are missing from our page, or a stale model price), `inbound` (<3 internal links).
`apply_data_refresh.py` fixes stale model API prices from `data/pricing.ts` in code (L2, own commit)
and leaves derived sentences in `fact-fixes.json` for the planners.

## Phase 2 — Plan (parallel planner subagents, ONE message)

Once for the run: `bash .claude/tools/load-standards.sh "page-1-2-no-clicks-pass" "phase-2"` (git add the
standards ledger) and `python3 scripts/lib/content_gen.py preflight` (a failing preflight stops all L4
work — never write the prose by hand instead).

Split the queue into batches of ~4 and launch the planners as several `Agent` calls in ONE message
(`run_in_background: false` — blocking AND parallel; never background one). Each gets
`scripts/page12/PLANNER_TASK.md`, its slug list and `$P`. Planners verify facts against vendor pages
(WebFetch), write `fact-edits.json` for every outdated sentence on the WHOLE page, and write `plan.json`
(+ `section.prompt.md` and `allowed-urls.txt` for an answer block) — never data files, never prose.

## Phase 3 — Generate (parallel API calls)

```bash
GEMINI_API_KEY=… scripts/rank_drop/generate_all.sh $P 6
```
Re-running retries only pages without output; a page that fails twice goes to `## Carried to next run`.

## Phase 4 — Splice + internal links + commit (code, ~1 min)

```bash
RD_ENGINE=page-1-2-no-clicks-pass python3 scripts/rank_drop/apply_sections.py --packets $P --date $D
python3 scripts/page12/inbound.py --packets $P --date $D
```
If `$P/applied.json` has any `REWORK:` error (the splice guard caught a generated section stating a
price that disagrees with `data/pricing.ts`), fix it NOW, not at the end: `rework.py` → `generate_all.sh`
→ `apply_sections.py --rework` (Phase 5 step 5 commands). A page whose section never lands ships its
fact fixes only and is listed under `## Carried to next run` (2026-10-07 run 3: gpt-5-6-api-pricing).
Per page, each its own commit: `FACT FIX` (the planner's old→new pairs), then the plan (`SNIPPET`/`RANK`:
meta and/or the answer block inserted before the first section), then `INBOUND LINKS` (link cards to
the page from up to 5 related pages, using the page's own new title/description).

## Phase 5 — Audit + fix on the remediation ladder (parallel auditors)

**Load and apply `.claude/commands/_remediation-ladder.md` IN FULL.** Every step is a script; do nothing by hand.

1. **Rung 0 — scoped lint:** `RD_ENGINE=page-1-2-no-clicks-pass python3 scripts/rank_drop/lint_new_text.py --packets $P`
   (only the text this run's commits added).
2. **Batches:** `RD_ENGINE=page-1-2-no-clicks-pass python3 scripts/rank_drop/audit_batches.py --packets $P`
3. **Audit (parallel, ONE message):** one auditor per brief, prompt exactly
   `Follow scripts/page12/AUDITOR_TASK.md for <brief path>. Date dir <date dir>.` Writing quality is
   graded on new text only; facts on the whole page (outdated facts anywhere → `fixes` pairs with a source).
4. **Rung 1 — FIX-IN-PLACE:** `RD_ENGINE=page-1-2-no-clicks-pass python3 scripts/rank_drop/apply_fixes.py --packets $P --date $D`
   → for each batch launch a fresh auditor with `Re-check per scripts/page12/AUDITOR_TASK.md § Re-check, batch <n>, $P/recheck.json.`
   Repeat until recheck.json is empty or only `rework` remains.
5. **Rung 2 — REWORK (new text only):** `RD_ENGINE=page-1-2-no-clicks-pass python3 scripts/rank_drop/rework.py --packets $P --date $D`
   → `scripts/rank_drop/generate_all.sh $P` → `RD_ENGINE=page-1-2-no-clicks-pass python3 scripts/rank_drop/apply_sections.py --packets $P --date $D --rework`
   → back to step 1 for those pages. A page past its 2nd rework is restored to the run base (`REVERT`).
   `out_of_scope` findings never fail a page; they go to the email's Flagged section.

## Phase 6 — Deploy once, verify, ledger, email

1. `.claude/scripts/deploy-run-to-main.sh push`
2. `RD_ENGINE=page-1-2-no-clicks-pass python3 scripts/rank_drop/finish_run.py --packets $P --date $D` — ledger
   row per PASSED page (with its pre-fix `baseline` from Google), live check, ONE IndexNow POST, commits
   packets + ledger.
3. `.claude/scripts/deploy-run-to-main.sh push` again, then email.

## MUST NOT
- Use any non-Google source for any measurement of our site, or continue after a hard fail.
- Call DataForSEO anywhere except `serp_read.py`, or use its output as a number about our site.
- Grade or rewrite pre-existing text for style; change any pre-existing sentence except an outdated/wrong fact (with an official source).
- Change a fact on a competitor snippet's word alone — the vendor's own page or data/pricing.ts is the only source.
- Delete, noindex, redirect, consolidate, change slugs or remove sections.
- Touch a page inside its 35-day cooldown or edited by any routine in the last 14 days.
- Ship anything that has not passed the Phase 5 audit.
- Do any Phase 4–6 step by hand. Every step has a script; if it breaks, fix the script.
