# Retained instruction understanding

Owner instruction, 2026-11-08. Applies across Mindmap Pass and content-producing callers. Remove repeated explanation of unchanged instructions; preserve complete rules and genuine understanding. This scoped update supersedes older wording demanding a new passage/meaning/application paragraph for EVERY unchanged source on every retry. It does not authorize lost-context reuse, transfer another role's understanding, skip changed rules, replay an old record as a new attestation, or weaken independent application review. Existing first-read requirements remain. Sites without detailed local comprehension records gain no new attestation workload.

## What remains current

Every actual role still reads its complete applicable instructions initially and follows the existing preflight delivery, source-freshness, handoff and independent review process. A later reviewer in the SAME actor/role/phase, same canonical job/scope and actual uninterrupted context may retain its own genuine source explanations. The helper compares exact current source hashes, actual bundle/actor/run/conversation/epoch identities and prior validated explanations. It permits the existing cross-run retained-context mechanism only when those actual identities and the original job remain valid. No actor may claim a retained context after compaction or a conversation switch.

At every new check the actual worker writes a fresh short confirmation that it still has access to and understands the rules, remembers the existing recall obligations, and that the retained explanations still apply. It explains the concrete current task, access basis and changed application/focus in its own words. This is not a generic yes/no checkbox and the helper never writes those statements. Changed/new instructions, changed applicability and active handoff/context packets receive fresh source-specific explanation. Missing or unclear access/understanding requires normal fresh reading without reuse, automatically; no user confirmation is needed.

## Existing detailed local protocol

1. Prepare the normal current preflight bundle with its existing `--reuse` pointing to the role's completed prior reading, actual fresh startup run ID, actual context/epoch and current canonical handoff. Read every newly delivered chunk completely. Keep the same reviewer context for targeted corrections only when it really remains available.
2. Use `python3 .claude/tools/instruction-understanding.py challenge --run-dir CURRENT_BUNDLE`. It reports how many unchanged rule explanations can be retained and exactly which sources still require fresh explanation. No correct-answer sheet or prefilled affirmation is generated.
3. Write a NEW immutable confirmation JSON containing `version: "retained-understanding-2026-11-08.1"`, the actual `bundleId`, `actor`, `runId`, `contextId`, `contextEpoch`, and `previousBundleId`. Write the actual current `task`, `accessEvidence` and `currentApplication` (at least 60 characters each; specific and truthful). State `currentContextAvailable`, `rulesUnderstood`, `contextRetained`, `unchangedApplicationsStillApply`, `recallStillUnderstood` and `reuseEligibleSources` only if genuinely true. Set `freshUnderstanding` to actual new entries for every changed/new/task source, using the existing exact source passage plus meaning and application requirements. Add a fresh entry for an unchanged source whenever its prior application no longer fits. Do not regenerate paragraphs for all the other unchanged sources.
4. Record it with `python3 .claude/tools/instruction-understanding.py record --run-dir CURRENT_BUNDLE --confirmation CURRENT_CONFIRMATION.json --out NEW_APPLICATION_VIEW.json`, then run the existing normal preflight `check` without passing the short confirmation as an old-format `--application`.

The compatibility view keeps original explanations explicitly attributed to their real prior application, plus newly authored changed-source explanations and the real current confirmation. It exists for the unchanged original validators; it is not 19 newly authored understanding statements. The helper never supplies a new audit verdict or publication authority. The original policy/helper bytes and their hashes stay intact, preserving existing valid receipts and all their coverage, freshness, recall, handoff and independent-application checks. A recorded application is never silently replaced.

## Existing independent review

Use `python3 .claude/tools/instruction-understanding.py inspect --run-dir CURRENT_BUNDLE --application NEW_APPLICATION_VIEW.json`. Review the compact current task/access/application explanation, changed-source entries, reuse count and exact original explanation reference. Do not dump the full mechanically expanded view back into the AI on every retry. If the original explanations have not been genuinely inspected by this reviewer in its retained context, inspect them once; otherwise retrieve them when a discrepancy, uncertainty or changed rule requires it.

Judge understanding AND application to the actual current artifacts and unresolved findings, using the existing chart/Phase 4 audit. An identity/hash check cannot prove comprehension. The rendered validator checks retained-explanation provenance again before publication, while existing local validators still inspect every required original/source-bound field. Keep genuine current understanding/application evidence in the normal review; do not fill a PASS merely because the helper accepted the record.

Use `sources --application NEW_APPLICATION_VIEW.json` to retain the additional confirmation/prior references alongside the normal complete bundle/chunk/handoff/source dependencies. Keep actual findings/counters and all independent review, SEO, professional/exclusion/testing and exact-live requirements. This creates no review round, counter reset, extra human gate, model/effort change or local-policy activation on another site.
