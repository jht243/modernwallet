# Phase 5 — Publish (all three lanes, one commit)

Mindmap (Phase 4c) has already written and audited everything this run ships. This phase only publishes: build check, ledgers, one commit, deploy, 200-verify, IndexNow, digest. It writes no prose. (Monetization check, content standard and the finance/YMYL guardrails are applied inside mindmap's phase-3 / phase-5-body / phase-4-audit.)

## 1. Sitemap + build check
The sitemap is build-generated by `@astrojs/sitemap` from the routes (filtered by `src/data/noindex.ts`) — do NOT hand-edit it. Run `npm run build` (prebuild search index → `astro build` → entity links → bundle-size gate); it doubles as the typecheck. Mechanical fixes only, otherwise revert the offending page (flagged in the digest, "build revert"). `dist/` is gitignored — never commit built output; the host builds from source on deploy.

## 2. Ledger writes (before the commit, so they ship in it)
- `reports/trend-pass/ledger.md`: one row per chart row mindmap touched this run — **KEPT** (built + shipped) or **DROPPED** (mindmap's reason: exists, winner protection, weak demand, SERP locked, metadata/redirect row, non-article, non-groundable YMYL fact, failed audit, build revert). Tag every row with its source (`trend` / `coverage` / `top-10`). **Exception:** an **over-cap** row is NOT written here — it stays eligible next run. There is no DEFERRED status.
  Use **HELD** (not DROPPED) for any row blocked only because a YMYL fact source was unreachable or not yet supplied — it re-competes next run (Phase 4c ledger statuses).
- `reports/trend-pass/trends.md`: **only if a NEW trend fired this run.** The trend row was already added in Phase 1 (status `MINED`) — fill in its "Coverage / pointers" with the pages shipped; the trend is now permanently caught. **On a run with no new trend, do NOT touch `trends.md`.**
- Save the run report `reports/trend-pass/<YYYY-MM-DD>.md` (trend verdict, classification tables, matrix, research pack path, mindmap chart path `reports/mindmap-pass/<YYYY-MM-DD>-trend-lane-c.md`, row outcomes).

## 3. Stale-base check → commit → push (concurrent-cron clobber hazard)
Other crons commit to `main` mid-run. Stage ONLY this run's files by explicit pathspec (never `git add -A`), then:
```bash
git fetch origin && git status
git diff --cached HEAD --numstat   # after staging: NO deletions you didn't make
```
Any staged deletion of a file you didn't touch = stale base — fix before committing. Then a single commit — name the driver of the run:
`trend-pass-auto <date>: <trend theme | coverage gap | mindmap> — N new pages (T from trend / C from query check / K from top-10), M enrichments (cap 25)`, then push per the trigger (publish-to-main): `git fetch origin main && git rebase origin/main && git push origin HEAD:main`. This repo auto-deploys from `main`. Never force-push `main`.

## 4. Verify 200s + IndexNow
After the deploy settles (poll the live site, allow a few minutes), `curl -s -o /dev/null -w "%{http_code}"` every new URL — all must be 200 before IndexNow. Submit new + enriched URLs to IndexNow (fallback key block in the orchestrator). Non-200s: report in the digest, skip them from IndexNow, do NOT roll back the run.

Assemble the details file and send per the orchestrator's Email section.
